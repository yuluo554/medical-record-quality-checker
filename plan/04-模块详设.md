# 04 模块详设

> 定稿 2026-10-03。schema 以 `src/mrqc/models/card.py`、`src/mrqc/rules/finding.py` 骨架代码为准，本文是设计说明与扩展约定。

## 1. 病历参数卡（统一中间表示）

所有部件解析后归一到一张参数卡；字段统一用 `FieldValue` 包装（值 + 单位 + 置信度 + 证据列表）。

```python
Evidence(part: str, quote: str)            # 证据：部件名 + 原文摘录（逐字）
FieldValue(value, unit="", confidence=1.0, evidence=[])  # confidence∈[0,1]
```

| 区块 | 字段 | 说明 |
|---|---|---|
| PatientInfo | name / gender / age / department / bed / admission_date / discharge_date / hospital_days | 全部合成 |
| Diagnosis | type(入院/出院/术前/术后) / name / icd10(可空) | 出院诊断是跨文档比对的锚点 |
| Surgery | name / incision_healing(切口愈合等级) / start_time / duration_min / surgeon / assistants / anesthesia | 与术前讨论/知情同意比对 |
| MedicationOrder | drug_name / dose / dose_unit / route / frequency / start_time / stop_time / is_antibiotic / antibiotic_level(非限制/限制/特殊) / purpose | 长期+临时医嘱合并归此 |
| LabResult | item_name / value / value_text / unit / abnormal_flag(↑↓/正常) / is_critical / report_time | 危急值闭环比对 |
| TimelineEvent | event(入院/术前讨论/知情同意/手术/术后首次病程/出院) / time / source_part | 时效性 + 时间逻辑比对 |
| Signature | role(住院/主治/主任/术者/审签) / name / date | 签名完整性 |
| RecordCard | 上述区块 + `parse_warnings[]`（解析告警，如无法识别的行） | |

序列化：`to_dict()` / `from_dict()` 双向；真值生成器直接产出参数卡形状的 truth.json，基准 F1 按**字段路径级**（如 `medications[0].dose`）对账。

## 2. 解析器（M2）

- `PartType` 枚举六类部件；`detect_part(text)` 按标题关键词识别部件归属；
- `BaseParser.parse(text, card) -> card`（向参数卡累加字段）；每部件一个解析器：`AdmissionParser / CourseParser / SurgeryParser / DischargeParser / OrderParser / LabParser`；
- **规则优先**：正则 + 槽位 + 合法性校验（数值超生理范围即丢弃并记 parse_warning）；LLM 兜底只处理低置信度字段；
- 工程陷阱防线（来自姊妹项目实测）：CRLF 残留统一处理、全角/半角数字与标点归一、逐字定位伪空格、中文路径、GBK 控制台（统一 `py -X utf8`）；
- 每个解析器用生成器样例做回归测试（M2 起落 data/samples 固定子集）。

## 3. 结论与规则引擎（M3）

**Finding（结论）**：`rule_id / rule_name / severity / basis / evidence[] / suggestion / status(pass|fail|need_confirm)`。

**Severity 枚举**：`LOW / MEDIUM / HIGH / CRITICAL / NEED_CONFIRM`（低/一般/较大/重大/待人工确认）。低置信度或多解情形一律 NEED_CONFIRM，不硬判。

**Basis（依据）**：`document(文件名+文号) / clause(条款定位) / quote(原文摘录)` —— 无 basis 的规则引擎拒绝加载（`status=待核对` 的依据只能产出 NEED_CONFIRM 结论）。

**规则 JSON schema**（存 `data/knowledge/rules/*.json`）：

```json
{
  "id": "C-DIAG-01",
  "name": "出院诊断与用药医嘱匹配",
  "type": "cross_consistency",
  "severity": "HIGH",
  "channel": "integrity | formal",
  "basis": {"document": "医疗质量安全核心制度要点", "document_no": "国卫医发〔2018〕8号",
             "clause": "病历管理制度", "quote": "…", "status": "已核对|待核对"},
  "only_if": {"any_keyword": ["出院记录", "手术记录"]},
  "params": {"anchor": "diagnoses(type=出院)", "compare": "medications"},
  "suggestion_template": "出院诊断“{diag}”缺少对应用药记录，请核对医嘱或补充诊断依据。"
}
```

**check_type 分派表**（引擎 `RULE_DISPATCH`）：

| check_type | 语义 | 示例规则 |
|---|---|---|
| required_field | 必填项存在性 | 缺主诉/缺出院诊断/缺签名 |
| timeliness | 时限比对（入院记录 24h、首次病程 8h 等，时限值以规范核对后入库，当前"待核对"） | F-TIME-* |
| cross_consistency | 参数卡内跨区块一致性 | 诊断-用药、手术-术前讨论、医嘱停止-出院时间 |
| medication_logic | 用药规则 | 抗菌药物越级无审批 |
| lab_logic | 检验/危急值闭环 | 危急值无处置记录 |
| signature_format | 签名/资质/格式 | 上级审签缺失 |
| timeline_logic | 时间轴逻辑矛盾 | 出院时间早于手术时间 |

**门控纪律**：`only_if` 关键词门控对**全部** check_type 生效（含 conditional 组合），新类目规则的门控关键词必须与既有语料互斥；引擎加载规则时校验门控存在性。

## 4. 知识库三层（M1 raw / M3 块+规则）

1. **raw**：规范原文 txt（`data/knowledge/raw/`），来源台账登记（渠道+URL+获取日期）；
2. **blocks**：条文块（`data/knowledge/blocks/*.json`：block_id/文号/条号/原文/向量由检索时计算），检索用纯 Python 余弦 top-k；
3. **rules**：机器可读规则表（§3 schema），每条必须挂 basis；`status=待核对` 的条目不得产出确定语气结论。

入库流程：获取原文 → 摘条文块（挂出处）→ 从条文派生规则参数（时限值、阈值）→ 人工核对 status。**查证优先于自证**：条文数值以官方原文为准，查不到登记"待核对"继续推进。

## 5. LLM 兜底（M4）

- 触发：仅 `FieldValue.confidence < 阈值` 的字段进入候选行压缩 → LLM 补抽；
- 输出契约：LLM 必须返回 `{field, source_part, quote}`；**quote 不是该部件原文子串 → 丢弃**；数值字段过合法性范围校验 → 超范围丢弃；
- 复核与行文：报告结论摘要可由 LLM 润色，但结论本身与依据引用来自规则引擎，逐字回验；
- 降级：未配置环境变量 / 超时 / 重试耗尽 / JSON 损坏（含截断修复）→ 全部走规则通路，测试 mock 覆盖全部失败路径。

## 6. 编排（M0 骨架已落位，M5 完整）

`pipeline/runner.py`：节点注册（名称+函数）→ 顺序执行 → 每节点耗时记录 → 任一节点抛异常即终止并保留已完成节点结果。`mrqc run --input <目录> [--report out.docx]`。

## 7. 缺陷类型 → 规则 → 生成器注入 对照表（M1/M3 的对账锚）

> 生成器植入缺陷与规则一一对应：**注入项记主期望 + 同一注入隐含的其余结论记 also_expect**（评测按"文档全部非 pass 集合"对账）。互斥坑（同一参数两注入打架）当场记录。

| 缺陷注入 | 注入通道 | 期望规则 | 通道 |
|---|---|---|---|
| 缺主诉/现病史等必填段 | 删段 | F-REQ-01 required_field | 形式 |
| 缺术者/上级签名 | 删行 | F-SIGN-01 signature_format | 形式 |
| 入院记录/首次病程/术后首次病程超时限 | 改时间戳 | F-TIME-01..03 timeliness（待核对） | 形式 |
| 出院诊断与用药不匹配（如肺炎无抗菌药） | 改诊断或删医嘱 | C-DIAG-01 cross_consistency | 内涵 |
| 手术记录与术前讨论术式不一致 | 改术式名 | C-SURG-01 cross_consistency | 内涵 |
| 手术记录术者与签名/医嘱不一致 | 改姓名 | C-SURG-02 cross_consistency | 内涵 |
| 危急值无病程处置记录 | 删病程行 | C-LAB-01 lab_logic | 内涵 |
| 重度贫血值无对应处置与诊断 | 改检验值 | C-LAB-02 lab_logic | 内涵 |
| 医嘱停止时间晚于出院时间 | 改医嘱时间 | C-ORD-01 cross_consistency | 内涵 |
| 抗菌药物越级使用无审批记录 | 加特殊级抗菌药 | C-ANTI-01 medication_logic | 内涵 |
| 术中用血无审核审批记录 | 加输血医嘱 | C-BLOOD-01 medication_logic | 内涵 |
| 出院时间早于手术时间 | 改时间戳 | C-TIME-01 timeline_logic | 内涵 |

M1 生成器按此表实现注入器；M3 规则按此表实现检查；M4 基准按此表算检出率/误报率。三方共用本表 ID，不得单方改名。

## 8. 评测基准（M2 出数 / M4 达标）

| 基准 | 输入 | 指标 | 门槛（M4） |
|---|---|---|---|
| `benchmarks/parse_f1.py` | data/samples 固定 seed 集 + truth.json | 字段路径级 P / R / F1 | F1 ≥ 0.95 |
| `benchmarks/e2e_detect.py` | data/paired 配对集（植入缺陷 vs 干净对照） | 检出率（按缺陷类型）、干净集误报数、依据关联率 | 干净集误报 = 0；检出率门槛 M3 定 |

零 API 依赖：基准只走规则通路，LLM 未配置即等效基准环境。
